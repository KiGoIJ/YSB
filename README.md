# Рабочая страница УСБ РУ ФСБ для GitHub Pages

Статический сайт для организационной/RP-среды: строгая официальная шапка + удобная рабочая панель УСБ, реестр документов, форма подготовки обращения и страницы регламента/архива.

> Важно: GitHub Pages является публичным статическим хостингом. Не размещайте в репозитории реальные персональные данные, материалы проверок, закрытые документы и сведения ограниченного доступа.

## Состав

- `index.html` – главная страница.
- `workflow.html` – рабочая панель УСБ.
- `documents.html` – реестр документов и скачивание шаблонов.
- `appeal.html` – локальная форма подготовки обращения.
- `regulation.html` – положение УСБ для просмотра.
- `archive.html` – журналы, архив и учет.
- `assets/css/style.css` – оформление.
- `assets/js/app.js` – поиск документов, локальная форма обращения, CSV-экспорт.
- `assets/img/emblem.png` – эмблема в шапке.
- `assets/docs/` – DOCX/XLSX/MD-документы отдельными файлами.
- `data/documents.json` – реестр файлов для страницы документов.

## Публикация на GitHub Pages

1. Создайте новый репозиторий на GitHub, например `usb-ru-site`.
2. Загрузите в репозиторий все файлы из этой папки.
3. Откройте `Settings → Pages`.
4. В разделе `Build and deployment` выберите:
   - Source: `Deploy from a branch`;
   - Branch: `main`;
   - Folder: `/root`.
5. Сохраните настройки.
6. Через 1–2 минуты сайт будет доступен по адресу:

```text
https://USERNAME.github.io/usb-ru-site/
```

## Как обновлять документы

1. Замените или добавьте файл в `assets/docs/`.
2. Обновите `data/documents.json`: добавьте название, категорию, описание, путь и размер файла.
3. Загрузите изменения на GitHub.

## Ограничения

- Форма обращения не отправляет данные на сервер.
- Локальный журнал хранится только в браузере пользователя через `localStorage`.
- Для реальной закрытой приемной нужен отдельный сервер, авторизация и контроль доступа.
